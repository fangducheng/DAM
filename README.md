# Enterprise DAM

Private enterprise digital asset management for controlled collaboration between organizations.

## Local prerequisites

- Node.js 24+
- pnpm 10+
- Docker Desktop with Linux containers

## Start the foundation stack

```powershell
Copy-Item .env.example .env
pnpm install
pnpm infra:up
pnpm db:migrate
pnpm dev
```

The web console runs at `http://localhost:5173`, the API at `http://localhost:3000`,
and OpenAPI documentation at `http://localhost:3000/api/docs`.

The local PostgreSQL host port is `5433` because port `5432` is already reserved by
another local project.


## 测试策略（平衡质量与速度）
1. 分级验证：核心逻辑（状态变更、数据持久化、权限校验、支付/登录流程）必须验证；UI 文案、样式、样板代码只需代码审查，不跑测试。
2. 每个改动路径只测 1 轮：1 次正常路径 + 最多 1 次该路径上真实存在的关键异常（例如登录只测：正确凭据登入 + 错误密码被拒）。通过即止，禁止重复运行。
3. 边界测试只做两类：需求里明确提到的；业务中真实会发生且出错会造成实际损失的（如金额、账号锁定）。其余边界场景（超长输入、并发、特殊字符等）用代码审查排查，不靠运行测试。
4. 对抗性审查不依赖跑测试：交付前自己以攻击者视角审查代码（越权、注入、空指针、状态竞态），发现问题才修，没问题不跑额外测试。
5. 功能齐全靠需求清单保证：交付前逐条对照原始需求核对实现，任何未实现项必须列出说明，不得以"没测"为由遗漏。
6. 全套测试套件只在两种情况下运行：改动确实影响核心流程，或用户明确要求。

    28 +   - 设计经确认后再写实施计划和代码；普通小型修复使用快速通道，不额外制造文档和抽象。

    43 +## Bug 修复策略
    44 +
    45 +1. **按业务优先级和风险排序**
    46 +   - 用户最新确认的测试 Bug 优先于旧功能计划；安全、权限、数据损失和核心流程问题优先于纯视觉问题。
    47 +   - 先复现并定位根因，不用表面绕过掩盖模型、状态或数据一致性问题。
    48 +
    49 +2. **控制调查与改动范围**
    50 +   - 首轮只检查目标文件、直接调用方和直接测试；只有出现具体风险证据时才扩大范围。
    51 +   - 修复覆盖根因及其直接契约，避免顺手重构无关模块，也不得回退已经确认的安全边界。
    52 +
    53 +3. **按风险分级验证**
    54 +   - 每条改动路径默认验证一次正常路径，并最多增加一次真实且高风险的异常路径。
    55 +   - 权限、认证、租户隔离、数据持久化、上传、永久删除和其他不可逆流程必须执行针对性测试。
    56 +   - 纯文案、样式和常规布局以代码审查、类型检查和构建为主；只有核心前端接线发生重大变化时才运行最小 UI 冒烟。
    57 +
    58 +4. **避免无效重复测试**
    59 +   - 同一组相关修改完成后集中验证一次；通过且代码未变化时不重复运行。
    60 +   - 验证失败后只重跑失败项和直接受影响路径，除非改动触及认证、权限、数据库迁移、公共契约或构建配置等全局边界。
    61 +
    62 +5. **交付前进行对抗性审查**
    63 +   - 从越权、租户隔离、注入、敏感信息泄露、空值、并发竞态和不可逆操作角度审查改动。
    64 +   - 逐条对照原始需求；任何未实现、部分实现或受环境限制的事项必须明确列出，不能用“尚未测试”代替实现。
