# 身份与权限迭代设计

## 1. 决策摘要

本迭代建立企业 DAM 的身份、会话和权限基础。系统采用“协作域、法人公司、业务空间”
三层模型，将人员身份与资料所有权分开：一个自然人在同一协作域只有一个账号，但可同时
任职于母公司、子公司或共享服务团队。空间既可以归协作域所有，也可以归某个法人公司
所有。

账号不开放公开注册。平台管理员创建协作域和首位公司管理员，公司管理员邀请员工。
平台管理员和公司管理员强制使用 TOTP MFA，普通员工是否强制 MFA 由协作域安全策略
决定。

授权采用空间 RBAC 与资源 ACL 组合。空间角色提供默认权限，文件夹 ACL 向下继承，
单文件 ACL 处理少量例外。显式拒绝优先于允许，无授权时默认拒绝。

## 2. 范围

本迭代包含：

- 协作域、法人公司、母子公司层级和用户多公司任职关系。
- 管理员邀请、密码设置、登录、TOTP、恢复码和会话管理。
- 平台、公司和空间系统角色及权限目录。
- 集团共享空间、公司私有空间和 `Restricted` 受限空间成员。
- 文件夹权限继承、单文件 ACL、权限计算和缓存失效。
- 登录、用户、空间成员、权限管理所需的前后端页面和接口。
- 统一错误协议、用户提示、审计事件和自动化测试。

本迭代不包含：

- LDAP、AD、OIDC 或 SAML 单点登录。
- 匿名分享链接和无需账号的外部访问。
- 文件上传、版本、预览和下载地址签发的完整业务实现；本迭代只定义并测试这些操作的
  权限判定，具体资产流程在下一迭代实现。
- 自定义角色编辑器。首版使用经过验证的系统角色，保留以后开放自定义角色的表结构。

## 3. 核心概念

### 3.1 协作域 Tenant

`Tenant` 是统一账号、安全策略和审计的最上层边界。在母子公司场景中，它代表企业集团；
在独立公司共同部署场景中，它代表双方约定的协作域。

不同 Tenant 的用户、组织、空间和资源绝不参与同一次权限计算。

### 3.2 法人公司 Organization

`Organization` 代表资料责任可独立审计的法人公司，可通过 `parentOrganizationId` 表达
母子公司关系。公司管理员只管理被授权公司的成员和公司自有空间。

### 3.3 用户与任职关系

`User` 直接属于 Tenant，不再强制只属于一个 Organization。
`OrganizationMembership` 记录同一用户在多个公司的任职状态和公司级角色。因此，共享
后勤人员使用一个账号和一次 MFA，即可同时承担公司 A、公司 B 及集团共享服务职责。

### 3.4 群组 Group

群组可属于 Tenant 或某个 Organization。Tenant 级群组用于共享后勤、集团法务等跨公司
团队；Organization 级群组用于公司内部部门或项目组。

### 3.5 空间 Space

空间是业务协作和资料权限的外层边界，不等同于公司。空间所有权有两种：

- `TENANT`：集团共享服务、联合项目等共同资料。
- `ORGANIZATION`：公司私有合同、发票、人事资料等。

空间成员可以是用户、群组或公司。公司管理员身份不会自动获得其他公司空间的访问权。

## 4. 数据模型调整

在现有 Prisma 模型上进行以下迁移：

- 新增 `Tenant`，包含代码、名称、状态和安全策略关联。
- `Organization` 新增 `tenantId` 和可空的 `parentOrganizationId`。
- `User.organizationId` 调整为 `User.tenantId`。
- 新增 `OrganizationMembership`，唯一键为 `organizationId + userId`，记录状态、加入时间
  和公司级角色绑定。
- `Group` 新增 `tenantId`，`organizationId` 改为可空；为空表示 Tenant 级共享群组。
- `Space` 新增 `tenantId`、`ownerType`，`ownerOrganizationId` 改为可空。
- `SpaceMember` 支持 `Restricted` 系统角色。Restricted 默认没有内容权限，只能看到 ACL
  明确允许的目录和文件。
- 新增 `Invitation`，保存邀请类型、目标邮箱、Tenant、公司、角色、邀请人、令牌哈希、
  过期时间、接受时间和撤销时间。数据库不保存邀请明文令牌。
- `AuthSession` 新增令牌族标识、轮换关系、最后使用时间和撤销原因，用于检测 Refresh
  Token 重放并撤销整个令牌族。
- TOTP 密钥使用应用层信封加密。恢复码拆分为一次性哈希记录，使用后写入 `usedAt`。
- 新增 `TenantSecurityPolicy`，至少包含管理员强制 MFA、普通成员强制 MFA、Access Token
  时长、Refresh Token 时长和登录锁定阈值。
- 保留现有 `Role`、`RolePermission`、`RoleBinding`、`ResourceClosure` 和
  `ResourceAclEntry`，补充 Tenant 边界字段、约束和查询索引。

迁移必须保证所有主体、角色绑定、空间成员和 ACL 引用位于同一个 Tenant。Prisma 无法表达
的跨表约束由服务层校验和数据库触发器共同保护。

## 5. 身份与会话

### 5.1 邀请流程

1. 平台管理员创建 Tenant、首个 Organization 和首位 OrganizationAdmin。
2. 公司管理员按邮箱邀请员工，并选择公司任职关系和初始公司角色。
3. 邀请链接默认 24 小时有效、只能使用一次，可由管理员提前撤销。
4. 用户接受邀请时设置密码；若策略要求 MFA，则必须完成 TOTP 绑定后才能激活账号。
5. 不存在公开注册或仅凭公司代码加入的入口。

### 5.2 登录和 MFA

- 密码使用 Argon2id 哈希，参数由安全配置集中管理。
- 平台管理员和公司管理员强制 TOTP；普通成员遵循 Tenant 策略。
- TOTP 绑定必须经过一次有效验证码确认，之后生成一次性恢复码。
- 登录失败和 MFA 失败分别计数并限速，达到阈值后临时锁定。
- 用户状态沿用 `INVITED`、`ACTIVE`、`LOCKED`、`DISABLED`。停用账号会撤销全部会话。

### 5.3 Token 和会话

- Access Token 默认 15 分钟，仅保存在前端内存中。
- Refresh Token 默认 30 天，使用 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 传输，
  数据库只保存哈希。
- 每次刷新都轮换 Refresh Token。旧 Token 再次出现时视为重放，撤销整个令牌族。
- Access Token 至少包含 `sub`、`tenantId`、`sessionId` 和 `amr`，不携带完整权限清单。
- 退出、修改密码、管理员停用账号和异常重放都会撤销相应会话。
- 用户可查看自己的登录设备并撤销单个或全部会话。

## 6. 角色与权限目录

### 6.1 系统角色

- 平台级：`PlatformAdmin`、`PlatformAuditor`。
- 公司级：`OrganizationAdmin`、`OrganizationMember`。
- 空间级：`SpaceManager`、`Editor`、`Contributor`、`Viewer`、`Restricted`。

`PlatformAdmin` 的紧急运维访问必须产生高优先级审计事件。`PlatformAuditor` 默认只能读取
配置、权限和审计元数据，不能读取资产正文。

### 6.2 空间角色

- `SpaceManager`：管理空间、成员、目录权限和全部内容。
- `Editor`：查看、预览、下载、创建目录、上传、更新版本和修改元数据；不能管理成员或
  转移所有权。
- `Contributor`：上传和管理自己创建的内容，不能删除或覆盖他人内容。
- `Viewer`：查看、预览和下载。
- `Restricted`：只有进入空间的能力，内容权限全部由文件夹或文件 ACL 明确授予。

权限目录使用稳定代码，至少包含：

- `platform.manage`、`audit.read`
- `tenant.manage`、`organization.manage`、`organization.users.manage`
- `space.create`、`space.manage`、`space.members.manage`
- `node.view`、`node.preview`、`node.download`
- `node.create`、`node.update`、`node.delete`
- `node.permissions.manage`

## 7. 文件夹和文件 ACL

ACL 主体支持用户、群组和公司，可设置 `ALLOW`、`DENY` 和过期时间。

- 空间角色提供默认权限。
- 文件夹 ACL 自动向全部后代目录和文件继承。
- 单文件 ACL 只处理少量特殊合同或文件例外。
- 同一次判定中出现有效 DENY 时，最终结果为拒绝。
- 没有 `node.view` 的目录和文件不出现在列表、搜索结果、面包屑或路径提示中。
- ACL 不跨空间继承。
- 移动目录需要同时具备源目录更新、目标目录创建及必要的权限管理权。移动完成后按新父
  目录重新继承。
- 删除或停用用户、群组、公司、空间时，相关授权必须同步失效。

只分享单个目录时，先把主体加入空间并授予 Restricted，再在目标文件夹添加 ALLOW。
系统不创建不可审计的“隐形空间成员”。

## 8. 授权计算

`AuthorizationModule` 对所有接口使用统一算法：

1. 验证账号状态、Access Token、会话和 MFA 声明。
2. 根据 `tenantId` 拒绝所有跨 Tenant 引用。
3. 解析主体集合：当前用户、有效公司任职、有效群组和对应公司主体。
4. 计算平台和公司级角色绑定。
5. 查找空间成员关系并取得空间基础角色；非平台紧急访问且不是空间成员时拒绝。
6. 使用 `ResourceClosure` 一次查询目标节点全部祖先的有效 ACL。
7. 合并空间角色、继承 ACL 和目标文件 ACL，过滤过期项。
8. 任一匹配 DENY 立即拒绝；否则至少存在一个匹配 ALLOW 才通过。
9. 对下载、预览、权限修改等敏感操作写入审计事件。

PostgreSQL 是权限事实来源。Redis 可缓存主体集合和短期判定结果，但不得成为唯一依据。
成员、群组、角色或 ACL 变更时递增 Tenant 的 `authorizationVersion` 并失效相关缓存。
下载、预览和权限管理每次请求都执行最新授权判断。

## 9. 后端模块

- `IdentityModule`：邀请、凭据、TOTP、恢复码、登录、Token 轮换和会话撤销。
- `TenantModule`：协作域、安全策略、法人公司、任职关系和共享群组。
- `SpaceModule`：空间生命周期、所有权、成员和系统角色。
- `AuthorizationModule`：主体解析、权限目录、ACL 管理、策略计算和 Nest Guard。
- `AuditModule`：统一记录登录、成员变更、授权、拒绝和敏感操作。

模块通过明确的应用服务接口协作。控制器不直接拼接权限查询，业务服务也不能绕过统一
Guard 或策略服务签发下载地址。

## 10. API 与前端页面

首版 API 覆盖以下资源：

- Tenant 和 Organization 的创建、查询及安全策略。
- 邀请创建、撤销、接受和重新发送。
- 登录、MFA 挑战、刷新、退出和会话撤销。
- 用户、公司任职、群组及群组成员管理。
- 空间、空间成员、角色和 ACL 管理。
- 内部权限判定接口和审计事件查询。

前端提供：

- 登录、MFA 验证、首次绑定和恢复码页面。
- 用户个人会话与安全设置页面。
- 平台的 Tenant/公司管理页面。
- 公司用户、邀请、任职和群组管理页面。
- 空间列表、成员管理和文件夹权限面板。
- 权限来源说明，展示权限来自空间角色、哪个父目录或哪个显式拒绝。

## 11. 统一异常与用户交互

后端返回稳定错误码、安全消息和请求标识：

```json
{
  "statusCode": 403,
  "code": "ACCESS_DENIED",
  "message": "无权执行此操作",
  "requestId": "req_01..."
}
```

- `401 SESSION_EXPIRED`：前端提示登录已过期，保留当前地址后跳转登录。
- `403 ACCESS_DENIED`：对用户主动操作显示无权提示。
- `404 RESOURCE_NOT_FOUND`：显示“文件不存在或你无权查看”，避免资源枚举。
- `409 VERSION_CONFLICT`：提示数据已被其他用户更新并提供刷新操作。
- `410 INVITATION_EXPIRED`：邀请页提示联系管理员重新邀请。
- `429 TOO_MANY_ATTEMPTS`：显示等待时间并暂时禁用提交。
- `5xx`：显示通用故障消息和 `requestId`，不暴露堆栈、SQL 或内部路径。

前端使用统一 API 错误拦截器，并允许页面覆盖默认行为。字段校验显示在输入框下方；后台
轮询失败显示状态条；下载、删除、授权等主动操作使用消息提示或确认对话框。并发请求的
相同错误需要去重，避免连续弹窗。

## 12. 审计与安全

至少审计以下事件：邀请、登录成功和失败、MFA 失败、Token 重放、会话撤销、账号停用、
公司任职变化、群组变化、空间成员变化、ACL 变化、访问拒绝和敏感下载。

审计事件包含 Tenant、组织、操作者、目标、动作、结果、请求 ID、IP、User-Agent 和时间，
但不得保存密码、明文 Token、TOTP 密钥或恢复码。权限变更和审计写入应在同一事务中完成，
失败时整个管理操作回滚。

## 13. 测试设计

- 单元测试：表驱动权限矩阵，覆盖用户、群组、公司、空间角色、Restricted、父目录 ACL、
  单文件 ACL、过期授权和 DENY 优先。
- 单元测试：密码策略、TOTP 时间窗口、恢复码一次性使用、Refresh Token 轮换和重放检测。
- 集成测试：邀请到激活、登录到刷新、账号停用到会话撤销的完整状态变化。
- 集成测试：Tenant 隔离、用户多公司任职、共享服务组和缓存版本失效。
- 端到端测试：A/B 私有空间、集团共享空间、只授权单个文件夹和无权限资源隐藏。
- 安全测试：路径枚举、越权 ID 替换、跨 Tenant 引用、暴力登录、并发刷新和审计脱敏。
- 前端测试：错误码映射、登录跳转、字段错误、重复弹窗抑制和移动端权限面板布局。

## 14. 验收标准

- 同一用户用一个账号同时承担 A、B 和集团共享服务职责。
- A/B 私有空间互不泄露，共享空间可按目录继续隔离。
- Restricted 成员只看到明确授权的目录。
- 权限变更后旧缓存不能继续授权敏感操作。
- 所有管理员强制 MFA，普通员工遵循 Tenant 策略。
- Refresh Token 重放能撤销整个令牌族。
- 无权资源不能通过列表、搜索、直接 ID 或错误差异推断存在性。
- 前端对已定义错误码给出友好、可定位且不泄密的反馈。
- 格式、lint、Prisma 校验、类型检查、单元测试、集成测试和生产构建全部通过。
